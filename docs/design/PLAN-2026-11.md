# DSAMaxxing rebuild plan (2026-11-01)

The goal is one plain study website. Every page must pass one test: someone studying for the first time understands it at once and would feel it is worth paying for. When in doubt, remove.

Sources: `FEEDBACK-2026-11-01.md`, `../research/skills-2026-11.md`, `../research/rea-2026-11/`. Nothing here comes from the old brief or layouts.

## What is wrong underneath

Three causes sit behind most of the feedback, and the rebuild fixes them first.

1. Pages are drawn 1440px wide and zoomed to fit. That is why spacing and sizes never feel right. Pages will use normal web layout instead.
2. There are 28 page templates, each styled separately. They will share one frame and one style file.
3. The site is one 17MB file (4.5MB compressed). Everyone downloads every lesson on the first visit. It must be split before hosting.

Lesson text, stories, problems, tests and the runner are good and stay. The rebuild replaces the pages around them.

## Removed

- **Pages:** Leaderboard, Contests, Interview, Revisit, Auth, Briefing, Main, Welcome.
- **Features:** league, XP, the separate medals wall, calendar, guided tour, demo data, anything marked "coming soon".
- **Text:** "Why learn this?", slogans, story summaries under problems, story words outside story mode.
- **Themes:** all except light and dark.
- **Kept small:** the streak is one number on Home.
- **Basics:** its unique content moves into Start here. If there is none, it goes.

Nothing is lost for good: all removed content stays in git history.

## Shared layout

- **Top bar:** 52px, stays at the top.
- **Sidebar (course pages and lessons):** 240px, plain text list of sections and lessons, done ticks, current lesson highlighted. On phones it sits behind a Lessons button.
- **Content:** lessons have text 72 characters wide and pictures up to 900px. Grids and tables run up to 1360px, so side space gets used.
- **Bottom of a lesson:** Previous and Next. **Top of a lesson:** a Back link naming where it goes, such as "Back to Chapter 4".

## Sizes and colours

- **Type:** 18 body, 16 code, 14 labels, 22 / 26 / 32 headings. Nothing under 14. Body line height 1.6. Phones keep 18.
- **Spacing:** only 4, 8, 12, 16, 24, 32, 48.
- **Controls:** rows and buttons 40px, 44px for touch. One 6px corner radius.
- **Colour:** one accent for the main button and current item. Green easy, amber medium, red hard, always with the word. A tick for done. No gradients, glow or emoji.
- **Blocks:** blocks in a row are the same height, with a thin border and a slight highlight on hover.
- **Motion:** 100 to 200ms and only on hover and open. Teaching animations keep play, pause, step and speed.

The 1360px width overrides the skills' 1200px, because the owner asked to fill the side space.

## Each page

**Home.** Next lesson name, Continue button, and four tiles: lessons done, problems solved, streak, medals. Each tile shows a number and a small bar.

**Roadmap.** Tracks in order: Start here, DSA concepts, Patterns, Complexity, Git, System design, AI & ML. A grid of equal track blocks. Each shows its name, done out of total, and its lessons without clicking. No tabs and no folds. Long tracks show all lessons in columns.

**Problems.** Columns: title, topic, difficulty, done. Search box, then filters for topic, difficulty and done. Company tags appear on the problem page. A problem's story name never appears here.

**Problem.** Opens straight into the problem, split 45 / 55.
- Left: tabs at the top: Problem, Hints, Solution, History. The Problem tab has a Story switch that shows the animated story in the same pane.
- Hints open one at a time. The Solution tab asks once before showing the answer. Neither costs anything.
- Right: editor, tests below it, Run at the bottom right.
- Before the first run the panel says "Press Run to test your code". An unfinished answer says "Not yet: 0 of 3 tests pass" and shows the first failing test, not "Wrong answer".
- Previous and Next problem, with "4 of 75" in the set.
- Phone: statement, editor and tests stack, with a Run bar that stays on screen.

**Course front.** A one-line strip at the top on how the lessons work, then the grid of lessons, full width.

**Lesson.** Back link, title, picture or animation, text, Previous and Next. About content appears as plain sections in the page, not behind a tab or fold.

**Complexity.**
- Sections as real boxed tabs at the top, with the active one highlighted.
- Growth chart first, with a label on each curve, same colours, and the clicked curve pulses.
- "Input size tells you the target" directly under the chart.
- "How to work it out": a sentence saying what to do, an explanation of the numbered boxes, and no empty steps area.
- "Memory use": explain the six boxes, and hold the pane height steady between examples.
- Lists become equal clickable blocks. An ⓘ "How to use this" tip on every widget.

**Quick Bytes.** Key content visible straight away in equal blocks. Fewer sections, one filter by topic, and no click needed to read.

## Components

Top bar, sidebar, Back link, Previous/Next, block, block grid, table, tabs, filter, search box, tick, difficulty label, progress tile, ⓘ tip, hint list, editor pane, test panel, empty message (one line plus one action).

## Hosting

The site stays static, with no server yet. Split the output into one file per page, with lesson data loaded when needed. **Target:** first page under 300KB compressed. I recommend Cloudflare Pages: free, fast in India, and it needs no server. Payment and login come later and are not in this plan. Prices stay hidden.

## Build order

One step at a time. Each step ends with `npm test` plus screenshots at 1440 and 390. Each page gets a final review of its screenshots against the feedback list before merging.

| # | Step | Test |
|---|---|---|
| 0 | Merge finished content (AI batch 4, Levels 4 and 5, both beginner reviews) | `npm test`; lesson counts unchanged |
| 1 | New frame, style file and sizes; end the zoom | No page zoom; no horizontal scroll at 320, 390, 1024, 1440; keyboard reaches everything |
| 2 | Lesson page for all tracks, Back, Previous, Next | Every lesson opens; Back returns to its parent with scroll kept |
| 3 | Problem page | Python and JS run on 5 sample problems; story toggle, hints and solution work; phone stacks |
| 4 | Problems table and search | Filters and search work; no counts in search; two clicks at most from Home |
| 5 | Roadmap | One page with no tabs or folds; one click opens any lesson |
| 6 | Course fronts | Strip at top; grid full width; blocks equal height |
| 7 | Home | New and returning views; four numbers correct |
| 8 | Complexity | F17 to F24 each shown in a screenshot |
| 9 | Quick Bytes | Readable with no clicks |
| 10 | Remove pages and features; rename; clear story words and "Why learn this?" | Build fails on the old names, "Why learn this", story words outside story mode, "coming soon" |
| 11 | Split output and host a test copy | Runner works on the real host; first page under 300KB |
| 12 | Full browser test, accessibility and worst-case data pass | Every feedback item ticked with a screenshot |

Mechanical edits go to the cheapest helper, layout work to the middle one, and final review to the strongest. Steps 2 to 9 can run side by side once step 1 is finished, as each owns its own pages.

## Decisions

1. Medals stay as one of Home's four numbers. The separate medals wall goes.
2. Finished content merges first (step 0).
3. Owner's choice: Interview becomes a Timed switch on Problems, Revisit becomes a Due for review filter there, and Contests and Leaderboard go. This happens in step 10.
4. Hosting: Cloudflare Pages, as a test copy only. No real domain or account without the owner.

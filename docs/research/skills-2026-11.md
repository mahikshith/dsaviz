## 5. Rules by topic

Sources: AN = anthropics frontend-design, EK = Emil Kowalski, VG = Vercel Web Interface Guidelines, UX = ui-ux-pro-max quick-reference, IM = impeccable, TS = taste-skill (app-screens chapter unless "page"), KZ = design-motion-principles. Values are given as used; "needs adjusting" means a source value fails our size floor.

### Layout
- Squint test: with blur you can still tell primary, secondary and groups (IM layout) [S]
- Group by proximity before adding boxes or borders (IM) [S]. Nested cards are always wrong; same-size icon+heading+text cards are the lazy page structure (IM craft-floor) [S]
- Product/reading pages: predictable structure, stable density (IM) [S]. Operate mode brand lives in details, not decoration [S]
- Labelled sidebar width 210-292px, median 230 (TS) [S]; sidebar from 1024px up (UX adaptive-navigation) [S]
- Page margins 16-32px; content reaches the edges; never under 16px at any width (TS page layout) [S]
- Max width consistent on desktop (UX: max-w-6xl/7xl, about 1152-1280px) [S]
- Breakpoints 375/768/1024/1440 (UX) or 640/768/1024 (IM adapt); three are enough [S]
- Cards in one row share a bottom edge; no card stretched over empty space; four rows over 270px of empty card is a hole; a 250px void beside a tall panel is flagged (TS) [S]
- Cap dashboard lists at 4-6 rows plus "view all" (TS) [S]
- No hero header: 9 of 23 measured screens have no heading over 16px; median heading 24px (TS) [S]
- Z-index scale 0/10/20/40/100/1000 (UX) [S]. Mobile: dvh not vh; no horizontal scroll (UX) [S]
- Avoid modals when inline works (IM, UX) [S]

### Spacing scale
- 4-unit base; documented scale, no one-off values (IM layout) [S]
- Tiers 16/24/32/48 by hierarchy (UX pro-rules) [S]; 4pt/8dp rhythm (UX) [S]
- Field spacing: 16px between fields, 24px from description to first label, 16px to Save (TS forms) [S]
- Settings sections split by a 1px rule with 32px above and below (TS) [S]
- More space above a heading than below it (IM craft-floor) [S]
- Section gaps on marketing pages are 120-240px (TS page) [S] but rejected for us. Our cap of 48px between blocks is [I]

### Type scale
- Body floor 16px (IM, UX, VG mobile inputs) [S]; our 18px body is [I] (owner rule)
- Suggested UI scale 12/14/16/18/24/32 (UX font-scale) [S]; ratio 1.125-1.2 for product UI (IM operate) [S]; fixed rem not fluid for product UI (IM) [S]
- Line height 1.5-1.75 body (UX) [S]; measure 65-75ch (IM, UX, UX desktop 60-75); AN says under 80 chars; EK cheatsheet 65ch [S]
- Weights: headings 600-700, body 400, labels 500 (UX) [S]
- Labels 14px/400 in nav, 14px/500 form labels; table headers and group labels 12-13px in TS [S] (needs adjusting to 14)
- One family is often right for product UI (IM) [S]; two families only if clearly distinct (AN) [S]
- Tracking: tighter only on large headings (-0.02em, EK) [S]; no tight tracking on body (UX) [S]
- `font-variant-numeric: tabular-nums` for number columns (EK, VG, UX) [S]
- `text-wrap: balance` on headings, `pretty` on body (IM, VG) [S]
- Avoid: all-caps labels, accenting one word in a headline, eyebrow labels, monospace as "technical" costume (AN, IM) [S]

### Density
- Sidebar rows: 32px hit area on a 34px pitch is the commonest; roomy is 40-52px (TS) [S]
- Single-line data rows 36-53px, median 45; key-value rows 21-32px; table header row 36-40px (TS) [S]
- Controls in toolbars 28-40px, median 32-34; forms 38-40px (TS) [S]
- KPI values 16-40px, median 26; never 48px+; no icon circles or sparklines on KPIs (TS) [S]
- Colour is on data, not chrome: median 3% coloured pixels; most cards have no shadow (TS) [S]
- Operate surfaces can afford density: many rows, many labels (IM operate) [S]
- First 1440x900 screen should show the header and first rows of every block the page names (TS) [S]

### Navigation
- Current location visibly marked: neutral grey pill, radius about 8px, inset 8-14px, or brighter text on dark (TS) [S]; colour, weight or indicator (UX) [S]
- Nav items have text labels (icon plus text); icon-only hurts discoverability (UX) [S]
- Same nav placement on every page; do not mix tabs + sidebar + bottom nav at one level (UX) [S]
- Bottom nav max 5 items; not for sub-navigation (UX) [S]
- Use real links (`<a>`), Cmd/Ctrl/middle-click work (VG) [S]
- URL holds state: filters, tabs, pagination, expanded panels; Back restores scroll (VG, UX) [S]
- Skip-to-content link; scroll-margin-top on heading anchors (VG) [S]
- Breadcrumbs for 3+ levels (UX) [S]. Move focus to main content after route change (UX) [S]
- Group labels in nav: sentence case, grey, 12-13px, never uppercase (TS) [S] (needs adjusting to 14)
- Read pages: nav shows where you are and next/previous (IM mode-read) [S]

### Forms
- Label above the field, 14px at 500, 8-10px gap; no floating labels; no placeholder as label (TS, UX) [S]
- Inputs 38-40px, 1px border, one control height per context (TS) [S]; mobile input font at least 16px (VG) [S]
- Validate on blur, not each keystroke (UX) [S]; but also: accept free text, validate after (VG) [S]
- Error under the field, linked with aria-describedby, says cause and fix (UX, VG, IM) [S]; focus the first invalid field or an error summary (VG, UX) [S]
- Never block paste; submit stays enabled until the request starts, then spinner keeps the label (VG) [S]
- `autocomplete`, correct `type`/`inputmode`, no spellcheck on codes (VG) [S]
- Buttons name the action ("Save changes", not "Submit"); same name through the flow (AN) [S]
- One primary action per screen (UX) [S]
- Disabled controls stay readable and say why; disabled opacity 0.38-0.5 (UX 0.38-0.5, TS warns 1.4:1 is unreadable) [S]
- Confirm destructive actions or offer undo (VG, UX) [S]

### Empty states
- Say what will appear, why it matters, how to start (one action) (IM onboard) [S]
- Distinguish first use, user cleared, no results (suggest clearing filters), no permission, load error (retry) (IM) [S]
- Empty = invitation to act; errors explain cause and fix without apologising (AN) [S]
- Honest data states: zero prints 0, missing prints a grey dash, empty section keeps its frame; no "No data" picture (TS) [S]
- Use words of the subject in labels ("No problems solved yet") not generic nouns (TS) [S]
- Illustration optional: IM asks for visual interest, TS and our density goal do not; keep ours compact and text-first [I]
- Handle "1 problems": pluralise with `Intl.PluralRules` (EK) [S]; skeletons mirror final content (VG) [S]

### Accessibility
- Contrast 4.5:1 text, 3:1 large text (IM, UX) [S]; tint secondary text from the surface hue, not generic grey (IM) [S]
- Visible focus ring using `:focus-visible`; never `outline: none` without a replacement; sticky bars must not cover the focused element (VG, UX) [S]
- Hit target at least 24px (WCAG 2.2), 44px on touch; expand hit area if the visual is smaller (VG, UX) [S]
- Do not disable zoom (VG, UX) [S]
- Not colour alone; status needs icon or text (VG, UX, IM) [S]
- Semantic HTML before ARIA; sequential headings; `alt` or `alt=""`; `aria-live="polite"` for toasts and validation (VG, UX) [S]
- Keyboard works everywhere; drag/gesture actions have a click and keyboard alternative (VG) [S]
- Charts: colour-blind safe palette and a table alternative (VG, UX) [S]
- Pause control for any motion longer than 5 seconds next to other content (VG) [S]
- Increase contrast on hover/active/focus (VG) [S]; set `color-scheme` for dark themes (VG) [S]

### Motion
- Frequency gate: 100+ times a day, none; tens a day, drastically reduce; occasional, standard; rare, may delight (EK, KZ) [S]
- Never animate keyboard-initiated actions (EK) [S]
- UI animations under 300ms (EK) [S]; press 100-160ms, tooltip 125-200ms, dropdown 150-250ms, modal 200-500ms (EK) [S]; operate surfaces 150-250ms (IM) [S]; 100-150ms immediate, 150-300ms routine, 300-500ms layout/overlay (IM animate) [S]
- Easing: ease-out for enter/exit, ease-in-out for on-screen movement, ease for hover colour, linear for constant (EK) [S]. Strong curve `cubic-bezier(0.23, 1, 0.32, 1)` (EK) [S]. Never ease-in on UI (EK, IM) [S]
- Only animate transform and opacity; never `transition: all` (EK, VG) [S]
- Press feedback `scale(0.97)` on :active; never from `scale(0)`, start at 0.9-0.97 plus opacity (EK) [S]
- Prefer CSS transitions over keyframes for UI that can retrigger (EK) [S]
- Respect `prefers-reduced-motion`: remove movement, keep opacity/colour state changes (all) [S]
- Flag as "AI slop": pulsing indicators, blur entrances on many elements, hover-scale on all cards, staggered lists, bouncy springs on utility actions (KZ anti-checklist) [S]
- No orchestrated page-load sequences in product UI (IM operate) [S]
- Exit shorter than enter (about 60-70%) (UX) [S]; stagger 30-50ms (UX) [S] but stagger on utility lists is a flag (KZ) [S]
- Our teaching animations (step-through stories) count as content, not decoration [I]

### Decoration to refuse (supports "no decorative style")
- Gradient text; glass/blur as decoration; coloured side borders over 1px; hard offset shadows; sparklines or progress rings as filler; emoji as icons; section numbers unless the content is a sequence; eyebrow labels (IM craft-floor, AN) [S]
- Cream + serif + terracotta, black + one acid accent, hairline broadsheet, identical rounded cards with the same soft shadow are named as generated-look defaults (AN) [S]
- Where sources disagree, the stance "bold, distinctive identity" (AN, TS page rules, IM persuade mode) is dropped; the "operate/read" modes are kept [I]
